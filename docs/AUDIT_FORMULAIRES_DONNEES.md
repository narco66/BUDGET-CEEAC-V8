## Classification appliquée

- **Saisie** : donnée métier entrée par l’utilisateur et validée côté serveur.
- **Référentiel** : valeur choisie depuis PostgreSQL par l’API.
- **Héritée** : valeur reprise d’un dossier ou objet amont.
- **Calculée** : solde ou montant calculé par Laravel à partir des données persistées.
- **Système** : référence, audit, horodatage ou statut de workflow produit par le backend.

## Contrôles exécutés

- `AdministrationTest.php` : 16 tests réussis ; chargement des rôles/structures et rejet d’un rôle absent vérifiés.
- `OrdonnancementTest.php` : 4 tests réussis ; défaut de base appliqué sans préremplissage frontend.

- `PaiementTest.php` : 5 tests réussis ; paramètre caisse et refus lorsqu’il manque vérifiés.
- `AdministrationTest.php` : 17 tests réussis après ajout du CRUD de règle métier et vérification de son audit.
- `npm run build` : réussi. Vite signale toujours un bundle principal supérieur à 500 kB.
- Aucun test de navigateur/interaction React n’a été exécuté ; aucun framework de tests frontend n’est configuré dans `frontend/package.json`.

## Limites et suites

Les pages ont été inspectées statiquement avec leurs endpoints et validations proches, mais tous les scénarios de chaque formulaire n’ont pas été parcourus en navigateur. Les modules absents, l’édition générale des utilisateurs/tiers, les CRUD de rôles/référentiels, le référentiel de fonctions vide et les exigences de pièces d’engagement nécessitent des chantiers dédiés. Une certification exhaustive requiert aussi des tests UI et une revue métier des règles fiscales, signataires et pièces obligatoires.
